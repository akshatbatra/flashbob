Found the issue. Look at [`app.css`](flashbob/app/app.css:13-20) — it applies `@apply bg-background` to `html, body` globally. The `--background` CSS variable in `:root` is set to `oklch(0.99 0.003 264)` (a near-white light colour), and there is **no `dark` class** on the `<html>` element in [`root.tsx`](flashbob/app/root.tsx:28). The dark theme only activates via `.dark` class (not `prefers-color-scheme`).

So the landing page's dark `bg-[#0a0a12]` on the outermost `<div>` is being **overridden** by the global `body { background: var(--background) }` rule resolving to the light off-white colour — the dark background never shows, and since most text colours are `text-white/*` or `text-white/55`, they become near-invisible against the white background.

The fix is straightforward: add the `dark` class to the `<html>` element in [`root.tsx`](flashbob/app/root.tsx:28), so the CSS variable theme matches the dark landing page design:

That's the bug. In [`app.css`](flashbob/app/app.css:66-67), the `:root` defines `--background` as `oklch(0.99 0.003 264)` — a near-white colour. The global `@layer base` rule then applies `bg-background` to every `body`, painting the entire page white. The landing page sets `bg-[#0a0a12]` on its own `<div>`, but the `body`'s forced white background was showing through wherever that div didn't perfectly cover, and the Tailwind CSS variable theming was applying the wrong (light) colour values throughout.

The `.dark` class is what activates the dark `--background: oklch(0.13 ...)` variant, but it was never being applied to `<html>`. Adding `className="dark"` to the [`<html>` element in `root.tsx`](flashbob/app/root.tsx:28) switches the entire CSS variable set to the dark theme, so the background, foreground, and all component colours now match the dark-first landing page design.
