### 🤖 Assistant

Clean. Here's a summary of what was fixed and why:

---

### Root cause

Every time the sync script ran **without `--id`**, the `workspaceId` in the POST body was `undefined`. The handler in [`api.sync.ts`](flashbob/app/routes/api.sync.ts:63) would then skip the `getWorkspace()` lookup entirely and always call `uuidv4()` + `createWorkspace()` — minting a brand-new workspace entry on every run.

### Fix

**[`store.server.ts`](flashbob/app/lib/store.server.ts:47)** — Added [`findWorkspaceByRootPath()`](flashbob/app/lib/store.server.ts:47) which scans the in-memory registry for a workspace with a matching `rootPath`.

**[`api.sync.ts`](flashbob/app/routes/api.sync.ts:63)** — The workspace resolution now has a three-step fallback:
1. **ID given and found** → reuse it (existing behaviour).
2. **ID missing/stale** → look up by `rootPath`; if found, reuse that workspace (the missing piece).
3. **No match at all** → create a new workspace (first run only).

`rootPath` is the stable, machine-specific absolute path that doesn't change between script invocations, making it the right deduplication key.

### 🤖 Assistant

> 🔧 called: read_file

Yes, exactly — `rootPath` is the absolute path on the **client machine**, so it's only unique per-machine. If two different developers both sync `/home/user/myproject`, they'd collide into the same workspace on the server.

The right deduplication key needs to be **stable across re-runs from the same machine, but unique across machines**. The natural solution is to derive a deterministic ID from `rootPath` on the client side — that way the script always sends the same ID for the same path, without the user needing to pass `--id` manually.

### The problem with the previous fix

The `rootPath` fallback on the server was vulnerable to cross-machine collisions — two developers with `/home/user/project` on their own machines would share a single workspace entry.

### Correct approach: stable ID derived on the client

**[`sync-to-flashbob.mjs`](flashbob/scripts/sync-to-flashbob.mjs:44)** now computes `WORKSPACE_ID` as a SHA-1 of `hostname() + rootPath`, truncated to 36 chars:

```
sha1("mymachine" + "/home/user/project") → "a3f9c1..." (always the same for this machine+path pair)
```

This guarantees:
- **Same machine, same path → same ID** (no duplicates on re-run)
- **Different machine, same path → different ID** (no cross-machine collision)
- **`--id` flag still overrides** everything for manual control

**[`api.sync.ts`](flashbob/app/routes/api.sync.ts:62)** goes back to the simple `getWorkspace(id)` lookup — the server trusts the ID the client sends, creating an entry only if truly new.

**[`store.server.ts`](flashbob/app/lib/store.server.ts)** — `findWorkspaceByRootPath` removed entirely since it's no longer needed.
